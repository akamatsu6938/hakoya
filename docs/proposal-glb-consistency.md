# 相談のための案：glb にありえない形の整合性をとる仕組み

作者（2026-11-03）：「glb 上でありえないようなものが人的ミスやソフトの仕様であった場合に、整合性をとる仕組みも入れたい」。
まだ作っていません。相談のための材料です。

## 進め方の案

1. **見つける**：コードの検査に「整合性」の項目を足す。重なる壁・壁からはみ出す開口・開口どうしの重なり・床から浮いた部材・ほかとそろわない高さ（会社ルールとの小さな差）など。
2. **直し方は2通りに分ける**：
   - **はっきりしたもの**（小さな入力のぶれ。例：2370→2400）：自動で直し、「自動で直したこと」として一覧と修正の履歴に出す（取り消せる）。
   - **判断が要るもの**（重なり・図面との食い違い）：直す案にして、人が承認する（いまの検品・囲んで直すと同じ流れ）。
3. どちらにするかの決まり（例：差が何 mm 以内なら自動か）は、会社ルールに残す。

## 決めてほしいこと
- 自動で直してよい範囲（いまはドアの上端の 50mm だけ）。
- 「自動で直したこと」を、毎回どこまで見せるか（一覧に全部出すか、件数だけか）。
- 10件の glb が届いたら、まず全部に「見つける」をかけて、例を増やしてから決める、でよいか。
