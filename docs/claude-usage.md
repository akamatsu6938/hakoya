# Claude の使い方の記録（動画の材料）

## Claude Code がなかったらできなかったこと
- **2026-11-02**：工務店で働く作者が、日本語の仕様書（SPEC.md）だけを渡し、「施主名を絶対に外に出さない」仕組みを初日に作れた。書き込む前の見張り・コミット前の検査・自動テストを、Claude Code がフックとして組み込み、テストで止まることまで確かめた。人の注意ではなく、仕組みで守る形になった。

- **2026-11-02（夜）**：作者が食事に出ている1時間の間に、Claude Code が「答えの反映 → 番号の引き継ぎ → 修正の記録 → 模型の組み立て → 3MF → 試験片」まで進めた。並行してサブエージェントが BambuStudio のソースコードを読み、「外壁だけをざらざらにする設定」のキー名を突き止めた。英語のソースを読むこの調べ物は、作者ひとりではできなかった。
- **自分の目で確かめる**：Claude Code は、作った平面図と 3D を Edge の画面なしモードで撮影して自分で見て、「部屋が丸ごと壁に見える」「余分な壁がある」「三角が浮いている」などを、人に見せる前に見つけて直した。

- **2026-11-03（夜）**：作者が「10時間くらいあるから、計画を立てて自動承認で」と席を外している間に、Claude Code が計画を書き、8つの段階を1つずつ進めた。表で直す（階・屋根）→ 片流れ以外の屋根 → 複雑な凹凸 → 図面（jww）の読み取り → 社外用 exe → 公開前の確認の道具 → 動画の台本。段階ごとにテストを足し（210 → 300件近く）、コミットし、記録を書いた。
  - 下調べはサブエージェント2人に分けて並行（屋根と階の持ち方／exe と公開前の確認）。
  - 図面と模型の向きが 90° 違うことを、図面の線と模型の壁の重なりを数えて自分で見つけ、重ねた絵を作って目で確かめた。
  - 社外用 exe を自分で作り、中身（Claude Code 本体・キー）が入っていないことを道具で調べ、起動して断られることまで確かめた。その途中で「初めて起動した PC で物件の一覧がエラーになる」不具合を、別の PC で試す前に見つけて直した。
  - 間違えたこと（既存のテストのファイルを上書き）は、テストの数の変化で自分で気づいて戻し、docs/mistakes に残した。

## アプリの中で Claude が何をしているか
- **面ごとの検品**：6人の検品担当（南・北・東・西・平面・印刷）が同時に、模型の図と元の家（glb）の図を見比べて食い違いを探す。まとめ役が重複を除いて重要度順に並べ、決めた形の JSON で返す。
- **数値は作らない**：直す案は「どの部材の・どの値を・何に合わせて」（例：内壁の多数派の厚み）だけを返し、数値はアプリのコードが計算する。Claude が使えるのは HAKOYA の道具（家の要約・部材の一覧・面の図・検査の結果・直す案・質問）だけ。
- **つなぎ方は2通り（＋AI なし）**：自分用は Claude Agent SDK（サブエージェント・Skill・フック・アプリ内の道具）で 作者のプランを使う。社外用は使う会社の API キーで Messages API を直接呼び、同じ動きを自分で回す（Skill の文章を指示として渡し、まとめは構造化出力）。費用はトークン数から計算して画面に出す。
- **囲んで直す**：人が平面図で部材をぐるっと囲み、一言（例：「この壁厚だけおかしい。ほかとそろえて」）を書くと、Claude が検品と同じ道具で直す案を出す。どの部材が囲まれたかはコードが決め、Claude は「どれを・どの値を・何に合わせて」だけを決める。決まらないときは選択肢つきで聞き返す。
- 3D で囲んで直す（11/3）：3D の画面で軒を囲んで「図面だともう少し出ている」と書くと、アプリの Claude は数値を作らず「図面の軒の出はいくつですか」と選択肢つきで聞き返し、人が答えた数値（450）で直す案を出す。数値が人の文章にあるかはコードが確かめ、承認すると屋根の南だけが伸びる。
- 開発の Claude Code：3D の当たり判定が撮影で合わない原因を、当たり判定の絵を画面に貼り出して突き止めた（ヘッドレスの Edge で WebGL の絵だけ引き伸ばされて写る）。調査役のサブエージェント3人（2D の囲み・3D の画面・屋根とデータ）と設計役1人で計画を作った。
- 会社ルールの言語化（11/3）：アプリの Claude が、全物件の集計（コードが計算した「2件中2件で 480」など）と作者の答えを読み、「窓の上端は物件ごとに glb の値を使う」「引き込み戸の戸袋は壁として残す」のような会社の決まりを根拠つきの文にする。文の数値は根拠にあるものだけ（コードが確かめる）。承認した分だけ会社ルールに入り、次の検品・囲んで直すの Claude に渡る。根拠にない自分の解釈は、Claude 自身が「確かめてほしい」と書いた。
- 検品の当たり具合の試験（11/3）：物件A にわざと間違いを10件入れて（窓の幅・高さ・位置、窓や壁を消す、壁の厚み）検品すると、6人の面の担当とまとめ役が9件を見つけ、8件は glb の値に戻す直す案まで出した。誤った指摘は1件。採点はコードが行う（Claude に自分の答えを採点させない）。組み立てたあとに自動で検品を始めることもできる（設定で選ぶ）。
- 開発の Claude Code：誤った指摘が本当に誤りかを、組み立てた立体を高さごとに切って確かめた（玄関ドアの下の細い帯は、組み立てのコードがもう抜いていた）。見落とした1件も、検品の記録から「番号の抜けに気づいたが、glb の図では壁に見えなかった」と原因まで追った。


- 図面（jww）を根拠にする（11/3 夜）：アプリが平面図を模型に位置合わせし、窓の注記（品番と上端 FL+）と模型の窓を照合する（物件A は11件すべて一致）。検品の Claude は、表題欄を除いた平面図の画像を模型の図と同じ縮尺で見られ、図面の寸法・注記の番号（jww:plan:T31 など）を直す案の出どころにできる。数値はコードが図面から読む。
- 片流れ以外の屋根（11/3 夜）：屋根を「面の集まり」として読み、切妻・寄棟・L字の谷の屋根も組み立てる（試験用の家で確認。実物の glb は要検証）。
- 図面との照合（11/3 夜）：平面図の窓の注記（品番と上端）と、面ごとに位置を合わせた立面図の窓の線を、コードが模型の窓と比べる。試験と同じ間違いを入れた物件A で、**AI なしでも10件中6件**をコードが見つけた（Claude の検品は9件）。コードが確かな所を押さえ、Claude は図面の画像も見ながら残りを見比べる、という分担になった。
- 実物の切妻・寄棟（11/3 深夜）：作者が寝る前に置いてくれた4件の glb（寄棟・切妻・平屋2件）を、開発の Claude Code が夜のうちに「まとめて検査する道具」で通し、屋根が片流れと読まれていることに気づいた。屋根の部材の三角形を数と向きだけで調べ（施主名の入りうる文字は一切出さずに）、「Walk in home は屋根を面ごとに別の部材で書き出す」ことを突き止めて、まとめて読むように直した。重なり・閉じない屋根・離れた塊も、立体を切って場所を数で特定してから直した（当て推量で直さない）。
- glb にありえない形（11/3 深夜）：同じ所に壁が2枚・はみ出す開口などを、コードが見つけて「要確認」に出す。見つけ方の決まりは、6件の実物で「拾うべきもの（物件A・B の壁の重なり）」と「拾ってはいけないもの（引き込み戸・連窓の枠）」を確かめて決めた。
- 物件の登録（11/3 深夜）：画面で glb と図面のフォルダを選んで登録する。場所やファイル名（施主名が入ることがある）はサーバーの中だけで持ち、画面にも Claude にも渡さない。
- 2階建てでの当たり具合（11/3 深夜）：物件B にわざと間違いを10件入れて（2階の窓・2階の壁・2階のドアを含む）検品すると、8件を見つけ、6件は glb の値に戻す直す案まで出した（誤り2件。1件は入れた間違いの結果として本当に起きている部品の重なり）。費用は 作者のプランで約 $2.7／回。Claude は間違いを入れていない回にも、立面図に描かれているのに glb にない小窓を見つけた（コードの照合の「注記に当たる窓がない」と同じ所）。
