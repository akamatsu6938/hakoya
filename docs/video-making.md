# 紹介動画の作り方（Claude Code で、録画から組み立てまで）

HAKOYA の紹介動画（約3分）は、**台本・画面の録画・CG・声・音楽・字幕・組み立てまで、すべて Claude Code が道具を作って動かしました。**
作者がしたのは「何を伝えたいかを言う」「下書きを見て感想を言う」「言い方を決める」「見本の家を作る」「YouTube に上げる」ことです。

> 動画の道具のコードは、このリポジトリには入れていません（提出用には、アプリの本体と記録だけを入れたため）。
> この文書に出てくる道具のファイル名（`tools/video/…`）は、開発のリポジトリの中の名前です。

## 3. 作り方の流れ

```
 作者：伝えたいこと ／ 見本の家（Walk in home で作った架空の家）
   │
   ▼
 Claude Code：台本 → 場面の表（scenes_v3.json）
   │
   ├─ 画面の録画 …… 画面なしの Edge を台本どおりに動かす（screen_record.mjs）
   │                 → 背景・窓・カーソル・寄り・早送りを付ける（screen_composite.py）
   ├─ MCP の場面 …… Claude Code を裏の端末で動かして記録 → 名前などを消す
   │                 → xterm.js で描き直す → HAKOYA の画面と左右に並べる（term/）
   ├─ CG ………………… three.js のページを画面なしの Edge で1コマずつ描く（hook_cg・print_cg・room_cg）
   ├─ 声 ………………… VOICEVOX（パソコンの中で動く）
   └─ 音楽・効果音 … numpy で波形をコードで作る（sfx.py）
   │
   ▼
 組み立て：1コマずつ描いて ffmpeg へ・字幕と札・音を -14 LUFS に（compose.py）
   │
   ▼
 確かめ：コマを並べた絵・取り出したコマ・音の大きさ
   │
   ▼
 作者が見て感想 ──→ 直して組み立て直す（下書き1〜8）──→ 作者が YouTube に上げる
```

### 3-1. 台本と場面の表
- 声の文・読み・置く秒・場面・字・効果音を、1つの JSON（`tools/video/v3/scenes_v3.json`）に書きます。最後の版は場面 28・声の文 40・効果音 42 か所。
- 場面ごとに「元の録画の何秒から何秒を、何秒で見せるか」（区間ごとに速さが決まる）・寄り・暗さ・ぼかしを書けます。
- 音楽は 100 BPM（1小節 2.4 秒）なので、場面は小節の頭で切りかえます。

### 3-2. 画面の自動録画（`screen_record.mjs`・`screen_composite.py`・`v3/rec/*.json`）
**人の手なしで、本物の HAKOYA の画面を録ります。** 画面なしの Edge を CDP（Edge を外から動かす窓口）で動かします。

- **台本（JSON）**：1歩ずつ「開く・待つ・押す・ドラッグ・打つ・キー・ホイール・寄る・区切り」を書きます（第3版の台本は7本）。
  - 押す所は CSS で指し、押す直前に画面の中の位置を調べます。
  - 待つ間（組み立て・Claude の考え中）は、その歩に「早送り」の倍率を書きます（例：組み立て ×16・検品 ×10）。
- **人らしい動き**：カーソルは始めと終わりがゆっくりで、少し弧を描きます。字は 1 秒に約 9 字で、間を少しゆらして打ちます。乱数は決まった値なので、同じ台本なら同じ動きです。
- **押してはいけない所で止まる**：環境設定（API キーの欄がある）・保存・書き出しなどは、押す前に止まります。料金・利用枠・データを消す確認の小窓は、キャンセルして止まります（本番の録画だけ、台本に書いた文の小窓を通します）。
- **コマの見張り**：PC が混むとコマが届かなくなり、待ちの 126 秒と最後の 30 秒ほどが録画に入らなかったことがありました。そこで、コマが 1.5 秒届かなければ画面を撮って足し、3 秒を超えたら送りを始め直すようにしました。
- **仕上げ**（`screen_composite.py`）：1920×1080・30fps。
  - 紺がかった炭色の背景・角の丸い窓（画面の 88%）と影。
  - カーソルは描き直し、記録した通り道を行き過ぎないなめらかな線（PCHIP）でつなぎます。押した所には金色の輪が広がります。
  - 寄る・戻るはゆっくり（最大 1.8 倍）。早送りの区間には「早送り ×N」の札を出します。

### 3-3. MCP の場面（`tools/video/term/`）
社外の会社の人が、自分の Claude Code から HAKOYA で検品する場面です。**本物の Claude Code を1回動かして録りました。**

1. 仮のデータの置き場に、見本の家を「見本の家」の名前で登録して組み立てる。
2. 他社用の HAKOYA を起こし、画面の録画を始める（3-2 の道具）。
3. Claude Code を、Windows の裏の端末（ConPTY。Python の部品 pywinpty）で起動する。MCP の hakoya がつながったのを確かめてから、`/mcp__hakoya__inspect 見本の家` を人の速さで打つ。
4. 端末に出た文字を時刻つきで記録する（asciicast v2 の形）。**文字はメモリの中だけに持ち、名前などを消してからファイルに書く**（`scrub.py`）。
5. 記録を、ブラウザの端末の描き方（xterm.js）で描き直し、画面なしの Edge で記録の時刻ごとに撮る（`term_render.mjs`）。
6. 端末と HAKOYA の録画を、壁の時計の時刻でそろえて左右に並べる（`side_by_side.py`）。カメラは「2つの窓 → 端末へ寄る → HAKOYA へ寄る → 引く」。Claude が道具を使っている間は早送りにします。

- はじめは作者が手で録りましたが、名前・メールアドレス・プラグインのエラーなどが映ったので、作者の「自動で撮れないか」で、この道具に替えました。
- HAKOYA の録画だけが途中で止まったときは、Claude を動かさずに HAKOYA の画面だけを録り直せます。

### 3-4. CG（`v3/hook_cg.py`・`v3/room_cg.py`・`print_cg.py`）
**CG は全部、three.js（アプリの 3D の画面と同じ r160）のページを、画面なしの Edge で1コマずつ描いたものです。** Blender などの 3D ソフトは使っていません。

- 材料は見本の家の、アプリが書き出したもの（元の glb・壁の線・模型の部品）だけです。道具は `data` という名前のフォルダを断ります。
- ページは「t 秒目の絵を描く」決まりで、1コマずつ撮って ffmpeg で MP4 にします（GPU で描く）。

| CG | 長さ | 中身 |
|---|---|---|
| 冒頭（hook_cg） | 4.8 秒 | 元の glb を色つきのまま回す → 金の光の幕で壁を読み取る → 壁が立ち、屋根が載る |
| 印刷（print_cg） | 18 秒 | 造形板の上で1層ずつ積み上がる → 机に部品が並ぶ → 組み上がる |
| 部屋（room_cg） | 7.2 秒 | 机の上の模型の部屋の中へ寄り、屋根はまっすぐ上へ外れる。逆回しを締めに使う |
| 屋根が降りる（room_cg の drop） | 2.4 秒 | 上から屋根がまっすぐ降りて載る（冒頭） |

- **本物らしく見せる工夫**（印刷の CG のページ。部屋の CG もこのページを使う）：
  - 1コマを 32 回少しずつずらして描き、重ねる。これで浅いピントのぼけ・なめらかな縁・動きのぶれ・やわらかい影が出る。
  - 部品の形は、アプリが書き出した印刷用の STL そのもの。
  - PLA の層の線（0.2mm ごと）と、外壁だけのざらざら（ファジースキン）を描く。
  - ノズルの道筋は、部品を高さごとに切った本当の輪郭をなぞる。

### 3-5. 声（VOICEVOX）
- VOICEVOX はパソコンの中で動きます。道具が VOICEVOX に文を送り、1文ずつ WAV にします。
- 声は**冥鳴ひまり（14 番）・速さ 1.06**。44人分の利用規約を VOICEVOX から読み、会社での利用に申し込みの要らない声を Claude Code が選びました。
- 字幕の文（text）と、読み上げの文（reading）を分けて書きます。英字や読み違えやすい言葉は、読みをかなで書きます（例：HAKOYA → はこや、Claude → クロード、お施主様 → おせしゅさま、14棟 → じゅうよんとう）。
- 同じ文・同じ声は、前に作った WAV を使い回します（直した文だけ作り直す）。

### 3-6. 音楽と効果音（`v3/sfx.py`）
**音楽も効果音も、numpy で波形をコードで作りました。ネットの素材は使っていません。**
- 音楽：F の調・100 BPM。和音の帯・鈴の分散和音・低い音・キック・ハイハットを、小節ごとの強さの表で並べます。山（9.6・59.2・148.0・174.4 秒）で主和音に戻って「ドン」。声の間は音楽を 7 dB 下げます。
- 効果音：16 種類（マウスのカチッ・屋根が載るコトッ・題字のドン・3D プリンターの静かな機械の音など）。最後の版で使ったのは 13 種類です。

### 3-7. 字幕と札
- 字は ASS（字幕の形式）で書き、ffmpeg で焼き込みます。字は Yu Gothic UI。
- 字幕のほか、章の札・左上の札（「イメージ（CG）」など）・指摘の札・金の枠・数字の札・題字を、場面の表から作ります。
- 「早送り ×N」の札は、場面の区間の速さ（1.3 倍より速い所）から自動で出します。

### 3-8. 組み立て（`v3/compose.py`）
- 場面の表から、1コマずつ Python で描いて ffmpeg に流します（コマの画像をためない）。全体で約 15〜25 分。
- つなぎは「切る・白く光る・重ねる」。最初と最後は黒から・黒へ。
- 声・効果音・音楽を混ぜ、全体を -14 LUFS にそろえます。
- 一部の秒だけ作って確かめることもできます。

### 3-9. 確かめ方
- **コマを並べた絵**：組み立てのときに、短い試作は 0.5 秒ごと、全体は 1 秒ごと（60 秒ずつ 3 枚）のコマを並べた絵を作り、Claude Code が見て直す所を探しました。
- **コマを取り出して見る**：CG・録画は、決めたコマだけ撮って見られます。袖壁の失敗（4 の下書き7）も、直したあとにコマを取り出して確かめました。
- **音の大きさを測る**：ffmpeg の ebur128 で、全体の大きさ（LUFS）と頂点（dBTP。-1 以下が目安）を出します。
- **字幕の文字**：字幕は組み立てのたびに文字のファイル（subs.ass）として書き出されます。外した言葉が残っていないかは、このファイルを文字で探して確かめます。
- **MCP の場面**：描いた端末の画面の字に、名前・メールアドレス・ユーザー名入りの場所が残っていないかを、コマごとに調べます（残っていたら MP4 を作らずに止まる）。数秒ごとのコマを並べた絵でも、目で確かめます。

## 5. 個人情報の守り

- **映すのは見本の家だけ**です（作者が Walk in home で作った架空の家）。お客様の家（実物の 14棟）は、動画では「14棟で確かめた」という数だけです。
- 動画の道具は、実物のデータの置き場（data フォルダ）を読まず、そこへ書き出しもしません。開発のサブエージェントにも data を読ませず、CG には見本の家の部品だけを写して渡しました。
- 画面の録画は画面なしの Edge なので、デスクトップ・通知・ユーザー名が映りません。
- MCP の場面：
  - 録画用の Claude Code では、メールアドレスと組織名を隠す公式の設定（IS_DEMO）と、場所を隠す設定（CLAUDE_CODE_HIDE_CWD）を使いました。
  - 録画用のフォルダは C ドライブの直下に置き、ユーザー名の入った場所を使いません。
  - 記録から、あいさつの名前・メールアドレス・ユーザー名入りの場所・この PC の Claude のアカウントの名前や組織名を、ファイルに書く前に同じ幅の「*」に置きかえます。プランの使い具合の行も空白にします。
  - そのあと描いた画面の字をコマごとに調べ、残っていれば止まります（3-9）。
- アプリの「出してはいけない言葉」の見張り（読み込みの画面の欄）も、動画の 2:39 ごろに映しています。録画にも使った見本用の起動で、この見張りの言葉が古いままだったのを見つけて直しました（11/6）。

## 6. 使った Claude Code の機能
