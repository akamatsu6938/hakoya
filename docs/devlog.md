### 段階2a：glb の読み取り・部材の仕分け・高さ
- `adapters/glb_reader.py`：glb を読み、部材（pobj の子ノード）ごとに三角形と部位のコードを取り出す。座標は pobj の座標系（mm・Z上）。
- `adapters/walkinhome.py`：GL・基礎天端・各階の FL・天井高を決め、部材の数を数えて `data/out/物件A/building.json` に書き出す。会社ルールとの照合も付ける。
- 出力の前に、施主名などが混ざっていないかを検査する（`core/privacy.py`）。
- 物件Aの結果：GL 0／基礎天端 480／1FL 624／天井高 FL+2,400。★の値とすべて一致。テスト36件合格。

### 詰まったことと解き方（2a）
- 基礎天端が 0 と出た。部位ごとに水平な面の高さを調べると、**基礎の本体（KISO_HONT）は側面と底だけで、天端の水平な面は別の部位（KISO_ILOW）に入っていた**。「本体の側面が届いている一番上」を基礎天端にして解決（水切りの 510 は使わない）。

### 2a でわかったこと（次の段階の材料）
- 座標は X・Y ともマイナス側（X −11,010〜−817、Y −11,010〜90）。屋根が −X 側に146mm出ているので、−X が西（低い側）。

### 段階2b：壁の作り直し（今回の山場）
- `adapters/walls.py`：SPEC §4-1 の手順で、面だけの glb から厚みのある壁を作り直す。外壁は外の面から内側へ162mmの帯、内壁は向かい合う仕上げ面の真ん中を中心線にして130mmで作り直す。
- `tools/plan_preview.py`：building.json から平面図の絵（plan.svg）を作る。
- 物件Aの結果：外形 10,192.8×11,100.0mm、外壁の厚み（測った値）162、内壁の仕上げ面の間（測った値）145。★とすべて一致。壁は外壁11・単独の壁4・内壁13。テスト46件合格（30度回した架空の家でも同じ結果）。
- Claude Code の使い方：自分で確認用の平面の絵（PNG）を描いて見ながら直した。数字だけでは分からない「ポーチの上の垂れ壁」「片面しかない単独の壁」に気づけた。

### 詰まったことと解き方（2b）
- 部屋が丸ごと「壁の範囲」に見えた → 確認用の絵の描き方の誤り（穴を塗り残していなかった）。データは正しかった。数字で確かめてから直した。
- ドアの位置に、ずれた余分な壁ができた → 建具の箱が壁より厚く（194 と 145）、はみ出した部分を予備の作り方が壁にしていた。予備の作り方では壁を作らず、「未解決の所」として一覧に出すようにした（SPEC §2-5：推測で埋めない）。
- 上がり框の段の面が「壁の仕上げ面」になり、玄関と廊下の間に壁ができかけた → 床から300mm以下しかない面は使わない。
- 入隅（へこんだ角）で外壁の帯の間に正方形のすき間 → 入隅を見つけて壁を厚み分伸ばす。ただし高さが重ならない面（ポーチの上の垂れ壁と、その下の壁）は角にしない。
- K50・K54 は片面しか単独の壁に入っていなかった → 厚みは上端・下端の板を含めた部材全体の広がりから取る。

### 段階2c：開口と屋根

- `adapters/roof.py`：屋根板の上の面・下の面から、片流れ 1.5/10・低い側は西・厚み100mm を出した。

### 2c でわかったこと
- 壁の外に吊る引き戸は、レール（OSTN）が穴の約2倍の長さで、天井より上にも出ている。本当の穴は床の敷居（KURI）の幅。FIX窓の KURI は上端にあるので敷居として使わない。
- **SPEC の「低い側の軒の出 約146mm」は軒樋（NTOI）の出だった。** 屋根板そのものは4辺とも外壁とそろう（軒の出ゼロ）。
- 平面図の窓の注記は13か所（SPEC）だが、glb の窓は11個。jww を読む段階で照らし合わせる。
