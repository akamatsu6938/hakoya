# 握りつぶした例外で、作った検査が一度も画面に出ていなかった（2026-11-04 朝に発見）

## 何が起きたか
- 11/3 深夜に「glb にありえない形を見つける検査」（core/consistency.py）を作り、AI なしの指摘（core/findings.py の code_findings）に「glb の整合性（要確認）」として出すようにした（15afc98）。
- code_findings の後ろの方（図面との照合の所）で `from core import overrides as ov` をもう一度書いていた。Python は関数の中に import があると、その名前を関数全体の「ローカル変数」と見なす。そのため、前の方の整合性の検査で `ov` を使った時点で UnboundLocalError になった。
- その例外は `except Exception: pass` で握りつぶしていたので、何も出ず、エラーにもならなかった。**AI なしの指摘に、整合性の指摘は一度も出ていなかった。**
- 11/3 の確かめは、検査の関数（find_all）を直接呼んだだけで、画面に出る道筋（code_findings）を通していなかった。devlog と checklist には「AI なしの指摘に出す」と書いていた。

## 見つけたきっかけ
- 11/4 朝のサブエージェントによる見直しで「例外の握りつぶしが、本当の不具合を隠すおそれ」と指摘された。握りつぶす代わりに「途中で止まりました（種類）」と出すように変えたら、試験で UnboundLocalError が出た。

## 直したこと
- 後ろの import を消した（ov はファイルの先頭で読んでいる）。物件A は W8・W13、物件B は W13・W14 の重なりが出るようになった。
- 整合性の検査・図面との照合が途中で止まったときは、黙らずに低い指摘として出す。
- 画面と同じ道筋（code_findings）で整合性の指摘が出ることを確かめるテストを足した（tests/test_consistency.py）。

## 次からの決まり
- 新しい検査を足したら、関数を直接呼ぶだけでなく、使う人が見る道筋（画面・code_findings・まとめて検査の表）で出ることを確かめる。
- `except Exception: pass` は使わない。止めたくないときも、止まったこと（例外の種類）は記録か指摘に残す。
