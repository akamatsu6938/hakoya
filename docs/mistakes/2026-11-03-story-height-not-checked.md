# 2026-11-03 物件B の階高の違い（3,000）に気づけなかった

## 何が起きたか
- 物件B の glb を調べたとき、1FL 624・2FL 3,624（階高 3,000）という数字は出ていた。
- 物件A と会社ルールの階高は 2,850。違いがあったのに、作者に「階高が変わってるの気づいてる？？」と言われるまで指摘できなかった。

## 原因
- 会社ルールと glb を比べる検査（`compare_with_rules`）が、基礎の天端・1FL・1階の天井高の3つだけで、階高（と2階の天井高）を比べていなかった。平屋の物件A だけで作ったため。
- 数字を並べて報告しただけで、会社ルールの値（`rules/jisha.yaml` の `story_height_mm`、コメントに「物件ごとに確認」とある）と自分で見比べなかった。

## 直したこと
- `compare_with_rules` に、2階から上の「階高（下の階の床→この階の床）」と「天井高」を足した。
- 作者の説明（基礎高・壁厚は会社で同じ、階高は物件ごとに変わる）に合わせ、会社ルールの選択肢（2,850・3,000）にある階高は食い違いにせず「物件ごとに変わる。glb の値を使う」と添える。選択肢にない値だけ食い違いにする。模型はいつも glb で測った階高で作る（言われなくても物件ごとの階高になる）。

## 次から
- 新しい物件を受け取ったら、SPEC §5-1 の値（GL〜基礎・GL〜1FL・階高・天井高・壁厚・窓の上端）を、会社ルールと1つずつ比べた表で報告する。数字を並べるだけにしない。
